What's next, and what we deliberately didn't build

This is a beta, not a finished product, and the honest version of that sentence matters more than the marketing version. Here's what's actually still open, and — just as important — what we looked at building and chose not to, at least not yet.

Deferred on purpose

  • No actuarial pricing model. The system produces control-maturity scores, not premiums, loss estimates, or compliance certifications. Turning scores into pricing is a carrier decision, not something this tool claims to do for them.
  • No automatic premium adjustment. An early design called for a 5% risk-score change to automatically trigger a premium adjustment. That's now an explicitly deferred later milestone, not a v1 feature — automating a financial decision off a young scoring model is exactly the kind of shortcut that erodes trust the first time it's wrong.
  • No multi-tenant carrier backend yet. The current carrier-side receiver handles the core intake and validation path; multi-tenant support for multiple carriers running independent books of business is on the roadmap, not in the beta.
  • No OAuth/SSO yet. Auth is functional for a beta but not yet built out for enterprise identity providers.
  • No signed connector distribution. An earlier design considered dynamically fetching compiled connector code at runtime — reviewed and rejected as a security risk (see what we learned). Any future connector distribution model will need real code-signing and publisher verification before it ships, not a checksum alone.

Genuinely open gaps, not deferred by choice

  • Containerization for both the assessment container and the carrier-side receiver is called for in the requirements and not yet complete.
  • Connector test coverage currently relies on fixtures rather than integration testing against live systems (starting with the GitHub connector).
  • No load testing yet against realistic assessment volume.
  • Governance framework label mapping (specifically mitre_airm) needs a clarification pass against the source framework before it's fully trustworthy.

Why the beta is gated

This is closed source, and access to the beta is gated behind a short technical application rather than an open signup form. That's not exclusivity for its own sake — the people whose feedback actually moves this forward are the ones already running complex, agent-heavy systems in production and who've had to think hard about exactly the failure modes this system screens for. If you're one of them, the application is on the next page.
