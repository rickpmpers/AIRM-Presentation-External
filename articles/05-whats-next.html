What's next, and what has been completed

AIRM has completed its core engineering phase: containerization, cryptographic dynamic package synthesis, multi-tenant IC Cloud isolation, closed-loop telemetry underwriting, actuarial loss modeling, and white-label branding readiness are all built, verified, and passing automated tests. Here is an honest accounting of what is delivered and the real frontiers ahead.

What has been completed & verified

  • Production containerization & deployment: Both the Go assessment workbench and Python IC Cloud have multi-stage Dockerfiles with unprivileged user execution, strict filesystem isolation, and production Docker Compose specifications (including docker-compose.secure.yml with automated TLS/mTLS certificate generation).
  • End-to-end closed loop proven: Verified in portal/e2e_test.go: intake of architecture specifications → dynamic IC Cloud package synthesis with HMAC-SHA256 signatures → bit-for-bit container verification → local telemetry collection with in-memory credentials → control screening → score-only carrier export → dynamic carrier underwriting rate adjustment (-2.5% premium adjustment).
  • Multi-tenant carrier backend & admin UI: IC Cloud features true multi-tenant isolation with per-tenant signing keys and a rate-limited admin UI/API deployed live at airm-ic.selfserved.ai and central.selfserved.ai/airm-ic/admin.
  • Actuarial loss engine & 75/25 blend: FAIR-style compound-Poisson / lognormal Monte Carlo simulation (EAL, VaR95, VaR99.5, TVaR99.5) and 75/25 AI-exclusion gap blend with public proxy benchmarks (airisk price and airisk iso-table).
  • Expanded governance & tool adapters: Catalog expanded to NIST AI RMF Generative AI Profile, ISO 42001/42005/23894, and OWASP 2025; normalized tool evidence adapters for Promptfoo, DeepEval, Giskard, ART, AIF360, and Evidently; and MITRE ATLAS crosswalk.
  • Offensive testing program schema: Three-phase governance lifecycle (TestGate → TestFinding → TestDisposition) across 10 attack families with closed-state validation.
  • Carrier white-label distribution layer (Decision 16): Configurable branding (config.BrandingConfig, GET /api/branding) enabling insurance carriers to distribute the customer container under their own brand.

The real open frontiers

  • Licensed ISO/Verisk loss-cost data: The current actuarial blend uses public Coalition 2024 claims observations as a transparent sector proxy. The next phase will integrate licensed ISO class/loss-cost data with state, policy form, limit, attachment, and trend fields.
  • Live non-commercial alpha pilot trials: Evaluating real-world multi-agent, multi-LLM architectures (such as OpenClaw operator swarms) against live operational metrics.
  • Adversarial execution tooling: Moving from the verified offensive-testing schema scaffolding to automated execution runners for red-teaming and prompt-injection harnesses.
  • Enterprise OAuth/SSO integration: Upgrading local bearer token authentication to enterprise identity provider federations (Okta, Azure AD).

Alpha/beta eligibility boundary

Alpha and beta testing remains strictly limited to non-commercial individuals and eligible personal or community participants operating OpenClaw or comparable personal-agent architectures. Commercial entities, AI vendors, and insurers are excluded from participating as alpha/beta testers. Engineering work on carrier white-label capability prepares the platform for a future commercial phase once alpha evidence is established.
